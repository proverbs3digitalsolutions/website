### Next — Sprint A: SMS reminders to guests

**Goal:** guests get texts they actually read, for check-in, check-out, balance due and booking confirmation.

| # | Atom | Done looks like |
|---|---|---|
| A1 | SMS provider adapter (provider chosen in BLOCKERS), configured by env var and a test mode | Sending in tests writes to an outbox. A missing key turns SMS off with a clear message. |
| A2 | Workspace SMS settings: on/off per reminder type, English or Taglish, monthly limit | Owners and managers can change them. Staff can't. |
| A3 | Scheduler sends due reminders, at most once per stay per type, and only to guests with a mobile number | No duplicates after a restart. Cancelled stays are skipped. |
| A4 | SMS log on the reservation, plus a usage count against the monthly limit | Each text shows its time, type and status. Sending stops at the limit and warns the owner. |
| A5 | Phone number normalising (09xx → +639xx) and opt-out ("STOP") handling if the provider supports it | Invalid numbers are flagged, not sent. |
| A6 | Tests, a browser check, and doc updates (PRD, TRD, APP-FLOW, BACKEND-SCHEMA, DECISIONS) | `npm test` passes. The docs match the code. |

Before starting, run `/proverbs3-dfss` analysis on this feature so the requirements (CTQs) are written into DECISIONS.MD and the atoms above can be checked against them.

### Carry list for QA round 9 (from the round 8 re-verify, 2026-10-14)

- **Group rename writes one row per room.** Renaming a booking group should write one activity row for the group edit, not one per room (`stays.js`, audit inside the room loop).
- **Cleaning checklist label.** A checklist edit reads "Count: 9"; it should read "Changed: Checklist items" (`housekeeping.js` and the settings label).
- **One shared filter fix (third round of this class).** The one-owner page shows the filter bar when a link carries a dropped value; the address keeps the dropped value (`owners.js`, `cleanerpay.js`); and the report and list date-range boxes in `filters.js` have the same half-typed-year problem and still accept 1900 to 2200. Fix once in the shared filter bar: drop bad values before the first paint, keep the address in step, and apply the 2000 to 2100 range.
- **Calendar loads while typing.** Go-to-date loads the calendar for each complete date passed through while typing; add a short wait before loading.
- **Focus after a redraw.** Keyboard focus falls to the page after pricing save or remove, cleaner pay Mark paid, Undo and rate save, rent Record, refund Void, inbox Cancel and Retry, and the channels dialog.
- **Security carries.** Google sign-up one-time nonce instead of the 30-minute window; transaction plus `FOR UPDATE` on the unlocked compare-then-write saves (booking page settings, workspace edit, pricing rule, cleaning checklist, inbox template and automation, stays guest and group, maintenance schedule); router empty-parameter check on the last segment only.
- **Staff deposit response.** It carries internal ids (`organization_id`, `booking_id`, `recorded_by`), same as the owner; consider an allow-list.
- **Small items.** Admin support reply uses a toast on an empty send; `reservation.updated` keeps before and after amounts (documented exception in D-84).
- **Not exercised in round 8 (live stage):** forgot-password server-error focus, Google path, applied discount display, lease branch of the room-type pick, payout over-statement for an owner without units, cleaner Mark paid form date, glass, refund Void name, maintenance link, plan limit, automations tie-break (code-checked only).

### Roadmap from the competitor research (2026-10-13)

Full reasoning is in `docs/research/00-SUMMARY.md`. Everything here is built inside BalayHub, with no integrations and no AI. Each phase still needs to be broken into atoms (and checked with `/proverbs3-dfss`) before it is built.
